## [Unreleased]

### Added
- The `jekyll-shapes` pack (PRD M1, the Jekyll ecosystem shape): three file checks over a site baked by Jekyll. `jekyll/excerpt-as-description` (FAIL) - a post with no front-matter `description` ships its rendered first paragraph as the meta description. This is `jekyll-seo-tag`'s own fallback (`drop.rb`: `page["description"] || page["excerpt"] || site.description`, capped at 100 words), so body prose leaks into the head and the tag can contradict the page. The check compares the description against the page's first `<p>` and fires on an exact match or a truncation of it; a tree with no `Begin Jekyll SEO tag` marker dockets BOUNDED, since the fallback is a seo-tag behavior. `jekyll/meta-double-shipped` (FAIL) - a layout carrying hand-written head meta AND `{% seo %}` emits `description` / `og:title` / `canonical` twice. `jekyll/hreflang-orphan` (FAIL) - a same-origin `hreflang` pointing at a language sibling that was never built (jekyll-seo-tag ships no hreflang support, so these are hand-authored); a page with no hreflang dockets BOUNDED. Grounded against real Jekyll 4.4.1 + jekyll-seo-tag 2.9.1 output, not the prose: a site was baked and its head inspected, which is how the excerpt fallback, the 100-word cap with an ellipsis, and the doubled-tag counts were learned rather than guessed. Negative test `test/jekyll-shapes-run.mjs` (wired into `npm test`, scaffolded fixtures, zero committed bytes): good bake clean 3/3, 5/5 bad bakes hitting exactly their id with no cross-check bleed, plus the null/empty/un-armed docket contracts and the external-hreflang scope guard. The runner arms a `jekyllTree` leg (`JEKYLL_SITE`, defaulting to `docs/_site`). Dogfooded on the repo's own docs bake: the double-ship check passes and the two seo-tag-specific checks docket BOUNDED honestly (the docs layout deliberately skips `jekyll-seo-tag`; freestruct owns the meta).
- The `wp-seo-shapes` pack (PRD M1, the WordPress ecosystem shape): three file checks over a baked WordPress site running a Yoast-shaped SEO plugin. `wp/head-seo-duplicated` (FAIL) - an SEO plugin and a theme/plugin both emit head SEO, so `description` / `og:title` / `og:description` / `twitter:title` ship twice (and where the values differ the page contradicts itself, since a crawler takes the first) and the JSON-LD schema graph ships twice. `wp/attachment-canonical` (FAIL) - a rendered WordPress attachment page inherits the front page canonical and/or is left indexable, so every uploaded image becomes an indexable near-duplicate of the home page; Yoast's `disable-attachment` default 301s attachment pages to the file, so a tree with no rendered attachment dockets BOUNDED. `wp/archive-canonical-drift` (FAIL) - a paginated archive whose canonical names a different page (usually page 1), which de-indexes its page 2+; a tree with no `/page/N/` archive dockets BOUNDED. Grounded against real WordPress 7.1.4 + Yoast SEO 28.8 output on SQLite, not the prose: the site was installed, baked, and inspected, which is how the missing-plain-`description`-unless-set behavior, the conflicting `og:title` pair (`Home` vs `Home - Acme WP`), the second `Organization` graph beside Yoast's `yoast-schema-graph`, the self-referential pagination canonicals, and the attachment canonicalising to the site root were all observed rather than assumed. Negative test `test/wp-seo-shapes-run.mjs` (wired into `npm test`, scaffolded fixtures, zero committed bytes): good bake clean 3/3, 5/5 bad bakes hitting exactly their id with no cross-check bleed, plus the null/empty/non-WordPress/no-plugin docket contracts and the clean-attachment scope guard. The runner arms a `wpTree` leg (`WP_SITE`).
- The `freestruct-shapes` pack (PRD M1, the second engine customer): five file checks over a docs site baked by the freestruct post-render SEO layer. `freestruct/build-drift` (FAIL) - pages carrying different `freestruct-build` ids mean a partial bake left stale pages; a tree with no stamp dockets BOUNDED. `freestruct/cache-bust-drift` (FAIL) - every `?v=` cache-bust param must equal the build hash, so an asset reference left from another build is caught. `freestruct/injection-duplicated` (FAIL) - the missing-only gate must not double-inject on a cache-hit rebuild, so a page carrying two `description`/`og:*`/`twitter:card` tags fails. `freestruct/canonical-absolute` (FAIL) - canonicals must be absolute and on one origin, which is the sub-path (`basePath`) contract that a root-relative canonical silently breaks. `freestruct/404-contract` (FAIL) - the generated 404 must carry `noindex` AND the full post-render pass (#11). Grounded against real freestruct 1.1.0 output, not the README: the docs tree was baked with freestruct and inspected, which is how the `?v=` to build-hash coupling and the missing-only idempotency were learned rather than guessed. Negative test `test/freestruct-shapes-run.mjs` (wired into `npm test`, scaffolded fixtures, zero committed bytes): good bake clean 5/5, 7/7 bad bakes hitting exactly their id with no cross-check bleed. The runner now arms a `freestructTree` leg (`FREESTRUCT_SITE`, defaulting to `docs/_site`).
- The `prestruct-shapes` pack (PRD M1, the engine's own contract): four file checks over a site baked by the prestruct engine. `prestruct/ssr-marker-missing` (FAIL) - an app mount (`<div id="root">`) without `data-server-rendered="true"` is a client-rendered page in a baked tree. The scoping is the point: a hand-authored shell page like `404.html` carries no mount and is correctly exempt, so a bare "does the marker appear anywhere" check would false-positive on it. `prestruct/deploy-id-drift` (FAIL) - pages carrying different `deploy-id`s, or a page missing the stamp, mean a partial bake left stale pages in `dist`; a tree with no `deploy-id` at all dockets BOUNDED, never a fake pass. `prestruct/canonical-ogurl-drift` (FAIL) - `og:url` disagreeing with `rel=canonical`. `prestruct/placeholder-leaked` (FAIL) - a shell template token (`your-site.example.com`, `Your Site`) surviving the inject-brand pass. Pure attribute reads, zero network. Negative test `test/prestruct-shapes-run.mjs` is permanent and wired into `npm test`: good bake clean, the 404 shell-exempt guard asserted explicitly, 5/5 bad bakes hitting exactly their id, and the no-deploy-id BOUNDED case. Dogfooded clean on the repo's own `dist/` (3 mounted pages stamped, 1 shell exempt).
- Config support (`poststruct.config.js`, `.mjs`, or `.json`), the PRD 4.4 contract that shipped docs had been promising with nothing behind it. Per-check level overrides (`fail`/`warn`/`off`, exact ids and `module/*` prefix globs, longest match wins so key order never decides), `scope.is404` to override the 404 heuristic, `scope.skip` globs to drop pages from the walk, and `dir` as the default target. Overrides are applied as a post-pass over findings rather than threaded into each check, so checks stay pure file readers. No config at all behaves exactly as before. A level that is not one of the three refuses loudly and names the value. Covered by `test/config-run.mjs` (wired into `npm test`).
- The `links` module (PRD M1): the internal link graph. `<a href>` targets are checked against the files that actually exist, with the same resolution order a static host uses (exact file, `<path>.html`, `<path>/index.html`, then a matching `_redirects` rule). A directory that exists without an `index.html` is a 404 on the host, so it is reported as broken rather than passed by a bare `existsSync`. Ids: `links/broken-internal` (FAIL), `links/redirect-target-missing` (FAIL, `_redirects` rules whose target is absent), `links/anchor-missing` (WARN by default, promotable via `anchorLevel: 'fail'`). `mailto:`/`tel:`, any scheme, and protocol-relative URLs are out of scope; the module never touches the network. Wired as `--module links` and into the default audit.
- `test/fixtures/good/_redirects` and `test/fixtures/bad/_redirects` carry the link fixtures; the good tree stays clean and the bad tree hits `links/broken-internal` + `links/redirect-target-missing` (FAIL) and `links/anchor-missing` (WARN), asserted in `test/run.mjs`.
- `README.md` declares the boundary against packstruct: what poststruct owns (the baked-artifact audit, its finding ids and levels, the pack loader), what it defers (manifest validation, pack naming, the `pack.json` schema, semver policy), and the shared vocabulary it consumes by version pin rather than copying. The three family house rules are named alongside it.
- `labs/TASKS.md` records the local docs-preview recipe: the Jekyll stack builds from a scratch copy of `docs/` with `BUNDLE_PATH` outside the repo, so docs tokens are verifiable pre-push and the tree is never the build root.

### Fixed
- `scripts/check-jekyll-filters.cjs` also refuses an unknown Liquid tag now, the same build-time class it already guarded: `{% seo %}` written in `docs/packs.md` prose killed the docs deploy with `Unknown tag 'seo'` (backticks are markdown, not Liquid escaping, and the docs deliberately ship no theme gem or `jekyll-seo-tag` plugin). Literal tags are exempted when wrapped in `{% raw %}`, and the tag set is the Jekyll 4.x core, so the failure is named in `lint:docs` with a file:line instead of surfacing in Jekyll's stack trace.
- `publish.yml`'s ladder gate read the ref NAME, not the version: `!startsWith(github.ref_name, 'v0.')` was true for a `workflow_dispatch` run on `main` or `staging` (where `ref_name` is the branch), so a 0.x tree could publish from CI - the exact thing `DEPLOY.md` says CI blocks. The gate is now a job that reads the version out of `package.json` and feeds the `publish` job's `if:`, so nothing at 0.x can publish regardless of how the run was triggered.
- `npm run site:build` installs `web/` before building, so the verb is self-contained for the Pages build command (the prior form assumed a separate `web/` install).
- Root `dist/` and `web/.prestruct/` are gitignored: the landing build product and the prestruct build cache no longer show up as untracked files.
- The eyestruct pin drift is gone: the `run-packs.mjs` refusal text and `AGENTS.md` name the `1.0.0` pin (the stale `0.9.0` mentions are corrected), and the pack-lane row no longer claims packs are absent from the core.
- The docs lane builds again: freestruct 1.1.0's strict link checker resolves root-absolute hrefs against the artifact root with no `basePath` awareness, so the `/poststruct/...` nav failed every page (100 findings, dhaupin/freestruct#32, fixed upstream but unpublished). `linkCheck: false` suspends that one class until a pinned release carries the fix; the rest of the strict gate stays on. `scripts/check-docs-links.cjs` now reads the repo's own `SITE_PREFIX` (`/poststruct`, not the ported `/prestruct`) and catches the doubled-prefix class.
- The Cloudflare Pages build runs again: the dashboard ships the Vite preset default build command (`npm run build`), which the root had no script for, so every deploy died at `Missing script: "build"`. The root now aliases `build` to `site:build`, so the preset default and the documented contract resolve to the same verb.
- CI now verifies `staging`, not just `main`: the `test` and `docs` workflows trigger on push and pull_request for both branches, so work is checked where it lands instead of at promotion time. The `docs` deploy job is gated to `main`, so a `staging` build proves the lane without publishing to Pages.
- The promotion loop closes: a merge-commit promotion leaves `main` one commit ahead of `staging` every time, so `AGENTS.md` now names the fast-forward step that settles it.

### Changed
- `eyestruct-shapes` encodes the slot jail, the freeze-era manifest delta from issue #42. A route row's optional `slot:` becomes part of a candidates-dir file name and a canon slot key, so it is a page name only (`[\w-]+`); a path shape (`/`, `..`, separators, dots, spaces) now refuses `MANIFEST_CORRUPT`, mirroring eyestruct 1.0.0's `lib/manifest.js`. Before this the pack returned clean on `slot: ../escape` while the engine refused it, a false negative in a surface the freeze already shipped. The negative test grew `bad-slot-escape` and the good canon now carries a legal `slot: home`, so the jail's both directions are pinned (parity verified against eyestruct 1.0.0 across nine slot values).
- The Cloudflare Pages contract is named in one place: `DEPLOY.md`, `README.md`, and `wrangler.toml` now state the project settings (root directory empty, build command `npm run site:build`, build output directory `dist`) and record why a `web` root breaks the build (Pages resolves `pages_build_output_dir` against the root, so `dist` lands outside the repository, and the root `functions/` directory drops out of the project).

### Removed
- The scheduled `linkcheck.yml` workflow: it invoked a `linkcheck` CLI mode that does not exist in 0.9.0, so the weekly lane would have gone red on the first push. The weekly external-link gate returns with the links module + `--check-external` (M1, tracked in labs/TASKS.md).

## [0.9.0] - 2026-10-23

### Added
- Audit engine over baked HTML (`src/core.mjs` walk + page model): the **head** module (title present + length band, description present + band, canonical present + absolute, OG(7) + Twitter(4) sets, og:image raster-format FAIL on SVG + dims warn, JSON-LD parse + LocalBusiness recommended fields, h1 sanity, the 404 noindex contract) and the **site** module (sitemap.xml existence + loc entries + lastmod, robots.txt `Sitemap:` pointer).
- Findings schema `{page, id, level, message}` with `{counts, findings}` under `--json`; exit contract: 0 clean/warns, 1 any FAIL, 2 usage error.
- CLI: `poststruct audit [dir] [--json]` (`bin/cli.mjs`).
- Self-audit fixture engine: `test/fixtures/good` must audit clean, `test/fixtures/bad` must hit exactly the expected FAIL ids (+ warn list); `test/run.mjs` asserts the exact sets (`npm test`).
- `package.json` ships `bin/`, `src/`, `LICENSE` in the tarball.

### Notes
- 0.9.x is the manual npm release ladder; `publish.yml` refuses 0.x versions at the gate. 1.0.0 flips OIDC trusted publishing (`id-token: write` provenance).
- Docs run on Jekyll + Pagefind + Freestruct at `docs.creadev.org/poststruct` via `.github/workflows/docs.yml`. Landing host is `poststruct.creadev.org` (Cloudflare Pages): the landing is shipped and live (web/ prerendered, `npm run site:build` bakes it), and its output is the first dogfood target (`npx poststruct audit dist/` gates clean on it).
