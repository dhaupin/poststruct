### Changed
- **The family table now reads the full family.** `govstruct` joined `FamilyStatusIsland`'s sibling table and the served CSP `connect-src` (both halves of the reader clause in the same round), and the `crashtest` row's page pointer moved `/dashboard` -> `/status` (the family status left crashtest's dashboard for its own route). `test/status.test.cjs` still pins the CSP-superset invariant, so the two halves cannot drift apart.
- **Cloudflare Pages setup is now the family shape: rooted at `web/`.** The CF config lives entirely inside `web/` (`web/public/_headers`, `web/public/_redirects`, and `web/functions/api/health.js`), matching eyestruct / packstruct / govstruct. The root `wrangler.toml` is removed, the root `dist/` copy machinery is gone, and `functions/` moved to `web/functions/`. Pages project settings: **root directory `web`**, build command `npm run build` (the Vite preset default), build output directory `dist`. `functions/` resolves relative to the root directory, so `web/functions/api/health.js` serves `GET /api/health`; the prior root-level `functions/` fell outside the project. Root scripts: `site:build` / `build` / `site:dev` retire in favor of `build:web` (`npm run build --prefix web`), the family name. `DEPLOY.md` and `README.md` name the new contract; the root `.gitignore` drops the dead root `dist/` line (`web/.gitignore` covers `web/dist/`).

### Added
- **npm-source pack loading** (`src/packs.mjs`, PRD M2): the shared loader both the campaign runner and any audit-side consumer use. Manifest validation against packstruct SPEC v1 (kebab-case name matching the dir, `schemaVersion` 1, dotted-semver version, non-empty description, a relative in-pack `entry`), and pack sources from a local path OR an installed npm package (`@poststruct/wp-seo-shapes`). An npm source resolves from the nearest `node_modules` carrying a `pack.json`; if it is not installed the load REFUSES with the fix named (`npm i -D <name>`) and never fetches. A pack name that resolves from two sources refuses to start (SPEC section 4, never silent dedupe). Armed via `--pack` flags, the config `packs:` array, or the `POSTSTRUCT_PACKS` env knob. Test `test/packs-run.mjs` (wired into `npm test`) pins npm-vs-path discrimination, local and npm resolution, the uninstalled refusal, every manifest violation, a missing entry, the root-scan-plus-spec union, and the collision refusal. The runner now loads through this shared validator and names any ledger problem before a non-zero exit.
- **Five M2 ecosystem shape packs**, each with a permanent negative test (good bake clean, every bad bake hits exactly its expected id, an absent tree dockets BOUNDED, never a fabricated pass):
  - `astro-shapes` - `astro/island-in-head` (a hydration island or module script stranded in `<head>`), `astro/trailing-slash-drift` (a canonical written for the other `build.format` shape), `astro/static-path-missing` (a same-origin link to a dynamic route `getStaticPaths` never emitted).
  - `shopify-liquid-shapes` - `shopify/liquid-leak` (an unrendered `{% comment %}` / `{% raw %}` / `{{ output }}` surviving the bake), `shopify/app-meta-duplicated` (a platform meta shipped twice by an installed app), `shopify/pagination-canonical` (a paginated collection canonicalising away from its own page).
  - `gatsby-shapes` - `gatsby/data-uri-og` (a base64 data-URI placeholder wired into `og:image`), `gatsby/noindex-leftover` (a sitemap-listed page left with `noindex`), `gatsby/sitemap-dupe` (a duplicate `<loc>`).
  - `hugo-shapes` - `hugo/summary-leak` (a list page shipping its `.Summary` as the meta description), `hugo/taxonomy-pagination` (a paginated taxonomy page canonicalising to page 1), `hugo/double-og` (an og partial wired twice).
  - `eleventy-shapes` - `eleventy/pagination-href-missing` (a canonical to a page `pagination.href` never built), `eleventy/relative-to-drift` (a `relativeTo`-built canonical off the deployed origin), `eleventy/collection-index-dupe` (two files claiming one URL).
  The five legs arm through `moduleCtx` (`astroTree`, `shopifyTree`, `gatsbyTree`, `hugoTree`, `eleventyTree`), each from a nested conventional build dir or an env override (`ASTRO_SITE`, `SHOPIFY_SITE`, `GATSBY_SITE`, `HUGO_SITE`, `ELEVENTY_SITE`).
- The `frontmatter` module (PRD M2) - the parsed key/type surface, the last piece of vant#7's requirements. The `language` module already treats a leading `---` block as a defined input part (splitting it so delimiters are never read as writing, and FAILing a malformed one); this module goes one step further and PARSES the block into a key/value surface, then grades it against a rule the config declares. That is the shape vant's `check-docs-frontmatter` gate needs to collapse in here. Ids: `frontmatter/key-missing` (FAIL - a required key is absent), `frontmatter/type-mismatch` (FAIL - a key is present but its value is not the declared type), `frontmatter/block-missing` (FAIL - a file a rule matches carries no block at all). Rules are per-file globs (`frontmatter.rules`: `files` glob, `required` key/type map, `types` key/type map); the type vocabulary is string/number/boolean/date/array/object/null and is validated at load, so an unknown declared type refuses loudly rather than silently passing every file it was meant to guard. The parser is a deliberately small YAML subset (top-level scalar keys, inline arrays, block sequences/maps) because that is what site frontmatter actually holds - it is not a general YAML engine and does not pretend to be; a construct it cannot read becomes a `type-mismatch` against the declared type, never a silent pass. The module is inert until a rule is configured, so the default audit is unchanged. Source-tree lane (`--module frontmatter`), deterministic (sorted walk). New test `test/frontmatter-run.mjs` (wired into `npm test`, scaffolded fixtures, zero committed bytes) pins the parser's type surface, each check's fire and pass direction, glob scoping, the inert-without-rules contract, the loud refusal on an unknown type, and two-run byte-identity. Dogfooded against the repo's own `docs/` frontmatter gate contract: clean, matching the existing `check-docs-frontmatter` PASS.
- The `language` module (PRD M2) and the **text-shaped input profile** (answers vant#7). Every other module grades baked HTML; this one grades PROSE, wherever it lives. The input profile is the part vant#7 asked for: the module reads baked pages' rendered text AND the source documents the config names (`language.textDirs`) - markdown bodies (code fenced/inline excluded as literal data, frontmatter split out), YAML values, JSON string values, and plain text - all through one `proseOf(kind, raw)` extractor, so a text lane and a bake lane share one contract. Ids: `language/dash-class` (FAIL by default; em/en/figure dash and horizontal bar, classes configurable so a project can allow one), `language/cliche` (WARN; a small generic lexicon - "delve", "tapestry", "unlock the potential", the "not just X, it is Y" construction, "when it comes to" - the flavorful house lexicon ships as an org voice pack, not core), `language/banned-term` (config or voice pack only; silent until a term is named, so core never invents a client's words), `language/lorem` (FAIL), `language/whitespace` (WARN; a non-breaking space or a zero-width character - invisible to a reader, visible to a machine), `language/frontmatter-unparsed` (FAIL; a leading `---` with no closing one). Findings carry `count` + `snippet` (vant#7 req 3) - CI consumes counts first, snippets second. Output is deterministic (vant#7 req 5): documents visited in sorted path order, findings in document order, no wall clock read. New test `test/language-run.mjs` (wired into `npm test`, scaffolded fixtures, zero committed bytes) pins every check's fire and pass direction plus the text profile per kind, the code-exclusion, the config knobs, and two-run byte-identity.
- The `feeds` module (PRD M3): the RSS/Atom contract over the baked tree. `feeds/alternate-dangling` (FAIL) - a page's `<link rel="alternate" type="application/rss+xml|atom+xml">` pointing at a feed that was never built (same-origin only; a cross-origin feed is another site's promise). `feeds/malformed` (FAIL) - a feed file that is not well-formed XML, or whose root element is not `<rss>`/`<feed>`, checked with a small tag-stack walker (zero deps, enough for the structural questions here). `feeds/item-link-dangling` (FAIL) - an item/entry link to a same-origin page that was not built. `feeds/empty` (WARN) - a well-formed feed with no items/entries. `feeds/no-self-link` (WARN) - no `rel="self"`, so aggregators cannot discover the feed URL. `.xml` files are only graded when a page declares them as a feed alternate, so `sitemap.xml` is never mistaken for a feed. New test `test/feeds-run.mjs` (wired into `npm test`) covers all five ids plus the Atom twin and the sitemap-scope guard.
- The `i18n` module (PRD M2): the language/locale contract over the baked tree, no network and no source archaeology. `i18n/lang-missing` (FAIL) - an `<html>` with no `lang` attribute, or an empty one. `i18n/lang-conflict` (FAIL) - the `<html lang>` disagreeing with a `content-language` meta or an `og:locale` on the same page, compared by PRIMARY subtag so `en-US` vs `en-GB` is not a conflict but `en` vs `fr` is. `i18n/hreflang-orphan` (FAIL) - a same-origin hreflang pointing at a page that was never built, so the language alternate 404s. `i18n/hreflang-no-return` (WARN) - a one-way pair inside the i18n graph (A names B, B declares alternates but names no alternate back); a WARN rather than a FAIL because a one-way hreflang is legal for a hub or an x-default. Only same-origin targets are checked; a cross-origin hreflang is another site's promise, out of scope the same way an external `<a href>` is out of the links module. Hreflang resolution reuses the links module's tree resolver, so both modules agree on what a baked host would serve. New test `test/i18n-a11y-run.mjs` (wired into `npm test`, scaffolded fixtures, zero committed bytes) pins each check's fire and pass directions.
- The `a11y-lite` module (PRD M2): the small set of mechanical accessibility failures every baked page should clear, with the honest boundary stated in the module and carried in the findings - a file reader cannot know whether an image is informative or decorative, so it only enforces the decisions the author actually made. `a11y/img-alt-missing` (FAIL) - an `<img>` with no `alt` at all, or a whitespace-only one; `alt=""` and `role="presentation"`/`role="none"` are RESPECTED as the explicit decorative choice. `a11y/form-label-missing` (FAIL) - an `<input>`/`<select>`/`<textarea>` with no `<label for>`, no wrapping `<label>`, and no `aria-label`/`aria-labelledby`/`title` (submit/button/reset/hidden/image inputs are exempt). `a11y/viewport-missing` (FAIL) - no viewport meta. `a11y/skip-link-absent` (WARN) - no in-page skip link to main content. The 404 shell is exempt, the same way it is exempt from the head contract. The module never claims WCAG conformance; it catches specific named failures.
- The external link lane (`--check-external`, PRD M1 close-out): the one network-bound check, opt-in so the default audit stays a pure file reader. `src/checks/external.mjs` collects every absolute `http(s)` `<a href>` in the baked tree and probes each one, reporting `links/external-broken` (WARN by default; promote via config once the external set is stable, since a remote host can fail for reasons the tree does not control). Shaped by the three facts a local check does not face: **transient failures are retried** (transport error, 5xx, 429 - a 4xx is the server's final answer), each URL is tried `HEAD`-first with a `GET` fallback only when the host rejects `HEAD` (405/501), and **answers are cached** to a JSON file (`--external-cache`) so a CI run is repeatable - a fresh entry is reused instead of re-fetched and expires after a week, so only new or stale URLs hit the wire. Probes are bounded by a concurrency limit (`--external-concurrency`, default 8) and a per-URL timeout (`--external-timeout`, default 10s), so one dead host cannot stall the run. `--json` gains an `external: {checked, cached, broken}` block. Hermetic test `test/external-run.mjs` pins every branch against a canned fetch (no socket opened): what counts as external, broken-to-WARN, retry-on-transient, no-retry-on-4xx, HEAD/GET fallback, transport failure caught, cache reuse, TTL expiry, and the concurrency cap. New `test/cli-run.mjs` drives the real binary and pins the argv contract (a valued flag's value is never mistaken for the dir; a valued flag with no value refuses with exit 2; a cached external run resolves offline).
- The canonical staging-flow page (`docs/staging.md`, poststruct#32): the four-rule integration-branch pattern the struct family shares - `staging` is permanent, CI covers it as well as `main`, any deploy job is gated to `main` by an explicit `if` (the load-bearing rule), and `staging` is fast-forwarded to `main` after every promotion. This repo is the reference implementation, and the page carries the proof from real runners (a `staging` push builds and skips the deploy; a `main` push builds and publishes). Linked from the docs nav and from `docs/ci.md`.
- The `family-status@1` dialect (#22): the web build now emits `web/public/status.json` from poststruct's own committed ledgers - `packs/eye-ledger.json` (the `packs` leg) and `labs/battery.json` (the `battery` leg) - plus the pack manifests under `packs/public/`. The emitter (`web/scripts/build-status.mjs`, zero-dep) is wired FIRST in the web build and the output is gitignored, so regeneration is the freshness and the served dialect can never lag the ledgers. The `/status` page and its `family-status` island read each sibling origin's `/status.json` back honestly: a member not serving the contract renders as "not serving the dialect yet", never a guessed row. `labs/battery.json` is now the single source of truth for the fixture corpus's expected FAIL/WARN ids - `test/run.mjs` reads it and the emitter counts it, so the served count can never drift from the test. `test/status.test.cjs` (wired into `npm test`) pins the emitter with temp-dir fixtures: the dialect fields, the RED-on-unknown-verdict rule, the manifest/rows intersection refusals, the empty-contract refusal, and the real tree's counts re-derived against the live ledgers.
- The `jekyll-shapes` pack (PRD M1, the Jekyll ecosystem shape): three file checks over a site baked by Jekyll. `jekyll/excerpt-as-description` (FAIL) - a post with no front-matter `description` ships its rendered first paragraph as the meta description. This is `jekyll-seo-tag`'s own fallback (`drop.rb`: `page["description"] || page["excerpt"] || site.description`, capped at 100 words), so body prose leaks into the head and the tag can contradict the page. The check compares the description against the page's first `<p>` and fires on an exact match or a truncation of it; a tree with no `Begin Jekyll SEO tag` marker dockets BOUNDED, since the fallback is a seo-tag behavior. `jekyll/meta-double-shipped` (FAIL) - a layout carrying hand-written head meta AND `{% seo %}` emits `description` / `og:title` / `canonical` twice. `jekyll/hreflang-orphan` (FAIL) - a same-origin `hreflang` pointing at a language sibling that was never built (jekyll-seo-tag ships no hreflang support, so these are hand-authored); a page with no hreflang dockets BOUNDED. Grounded against real Jekyll 4.4.1 + jekyll-seo-tag 2.9.1 output, not the prose: a site was baked and its head inspected, which is how the excerpt fallback, the 100-word cap with an ellipsis, and the doubled-tag counts were learned rather than guessed. Negative test `test/jekyll-shapes-run.mjs` (wired into `npm test`, scaffolded fixtures, zero committed bytes): good bake clean 3/3, 5/5 bad bakes hitting exactly their id with no cross-check bleed, plus the null/empty/un-armed docket contracts and the external-hreflang scope guard. The runner arms a `jekyllTree` leg (`JEKYLL_SITE`, defaulting to `docs/_site`). Dogfooded on the repo's own docs bake: the double-ship check passes and the two seo-tag-specific checks docket BOUNDED honestly (the docs layout deliberately skips `jekyll-seo-tag`; freestruct owns the meta).
- The `wp-seo-shapes` pack (PRD M1, the WordPress ecosystem shape): three file checks over a baked WordPress site running a Yoast-shaped SEO plugin. `wp/head-seo-duplicated` (FAIL) - an SEO plugin and a theme/plugin both emit head SEO, so `description` / `og:title` / `og:description` / `twitter:title` ship twice (and where the values differ the page contradicts itself, since a crawler takes the first) and the JSON-LD schema graph ships twice. `wp/attachment-canonical` (FAIL) - a rendered WordPress attachment page inherits the front page canonical and/or is left indexable, so every uploaded image becomes an indexable near-duplicate of the home page; Yoast's `disable-attachment` default 301s attachment pages to the file, so a tree with no rendered attachment dockets BOUNDED. `wp/archive-canonical-drift` (FAIL) - a paginated archive whose canonical names a different page (usually page 1), which de-indexes its page 2+; a tree with no `/page/N/` archive dockets BOUNDED. Grounded against real WordPress 7.1.4 + Yoast SEO 28.8 output on SQLite, not the prose: the site was installed, baked, and inspected, which is how the missing-plain-`description`-unless-set behavior, the conflicting `og:title` pair (`Home` vs `Home - Acme WP`), the second `Organization` graph beside Yoast's `yoast-schema-graph`, the self-referential pagination canonicals, and the attachment canonicalising to the site root were all observed rather than assumed. Negative test `test/wp-seo-shapes-run.mjs` (wired into `npm test`, scaffolded fixtures, zero committed bytes): good bake clean 3/3, 5/5 bad bakes hitting exactly their id with no cross-check bleed, plus the null/empty/non-WordPress/no-plugin docket contracts and the clean-attachment scope guard. The runner arms a `wpTree` leg (`WP_SITE`).
- The `freestruct-shapes` pack (PRD M1, the second engine customer): five file checks over a docs site baked by the freestruct post-render SEO layer. `freestruct/build-drift` (FAIL) - pages carrying different `freestruct-build` ids mean a partial bake left stale pages; a tree with no stamp dockets BOUNDED. `freestruct/cache-bust-drift` (FAIL) - every `?v=` cache-bust param must equal the build hash, so an asset reference left from another build is caught. `freestruct/injection-duplicated` (FAIL) - the missing-only gate must not double-inject on a cache-hit rebuild, so a page carrying two `description`/`og:*`/`twitter:card` tags fails. `freestruct/canonical-absolute` (FAIL) - canonicals must be absolute and on one origin, which is the sub-path (`basePath`) contract that a root-relative canonical silently breaks. `freestruct/404-contract` (FAIL) - the generated 404 must carry `noindex` AND the full post-render pass (#11). Grounded against real freestruct 1.1.0 output, not the README: the docs tree was baked with freestruct and inspected, which is how the `?v=` to build-hash coupling and the missing-only idempotency were learned rather than guessed. Negative test `test/freestruct-shapes-run.mjs` (wired into `npm test`, scaffolded fixtures, zero committed bytes): good bake clean 5/5, 7/7 bad bakes hitting exactly their id with no cross-check bleed. The runner now arms a `freestructTree` leg (`FREESTRUCT_SITE`, defaulting to `docs/_site`).
- The `prestruct-shapes` pack (PRD M1, the engine's own contract): four file checks over a site baked by the prestruct engine. `prestruct/ssr-marker-missing` (FAIL) - an app mount (`<div id="root">`) without `data-server-rendered="true"` is a client-rendered page in a baked tree. The scoping is the point: a hand-authored shell page like `404.html` carries no mount and is correctly exempt, so a bare "does the marker appear anywhere" check would false-positive on it. `prestruct/deploy-id-drift` (FAIL) - pages carrying different `deploy-id`s, or a page missing the stamp, mean a partial bake left stale pages in `dist`; a tree with no `deploy-id` at all dockets BOUNDED, never a fake pass. `prestruct/canonical-ogurl-drift` (FAIL) - `og:url` disagreeing with `rel=canonical`. `prestruct/placeholder-leaked` (FAIL) - a shell template token (`your-site.example.com`, `Your Site`) surviving the inject-brand pass. Pure attribute reads, zero network. Negative test `test/prestruct-shapes-run.mjs` is permanent and wired into `npm test`: good bake clean, the 404 shell-exempt guard asserted explicitly, 5/5 bad bakes hitting exactly their id, and the no-deploy-id BOUNDED case. Dogfooded clean on the repo's own `dist/` (3 mounted pages stamped, 1 shell exempt).
- Config support (`poststruct.config.js`, `.mjs`, or `.json`), the PRD 4.4 contract that shipped docs had been promising with nothing behind it. Per-check level overrides (`fail`/`warn`/`off`, exact ids and `module/*` prefix globs, longest match wins so key order never decides), `scope.is404` to override the 404 heuristic, `scope.skip` globs to drop pages from the walk, and `dir` as the default target. Overrides are applied as a post-pass over findings rather than threaded into each check, so checks stay pure file readers. No config at all behaves exactly as before. A level that is not one of the three refuses loudly and names the value. Covered by `test/config-run.mjs` (wired into `npm test`).
- The `links` module (PRD M1): the internal link graph. `<a href>` targets are checked against the files that actually exist, with the same resolution order a static host uses (exact file, `<path>.html`, `<path>/index.html`, then a matching `_redirects` rule). A directory that exists without an `index.html` is a 404 on the host, so it is reported as broken rather than passed by a bare `existsSync`. Ids: `links/broken-internal` (FAIL), `links/redirect-target-missing` (FAIL, `_redirects` rules whose target is absent), `links/anchor-missing` (WARN by default, promotable via `anchorLevel: 'fail'`). `mailto:`/`tel:`, any scheme, and protocol-relative URLs are out of scope; the module never touches the network. Wired as `--module links` and into the default audit.
- `test/fixtures/good/_redirects` and `test/fixtures/bad/_redirects` carry the link fixtures; the good tree stays clean and the bad tree hits `links/broken-internal` + `links/redirect-target-missing` (FAIL) and `links/anchor-missing` (WARN), asserted in `test/run.mjs`.
- `README.md` declares the boundary against packstruct: what poststruct owns (the baked-artifact audit, its finding ids and levels, the pack loader), what it defers (manifest validation, pack naming, the `pack.json` schema, semver policy), and the shared vocabulary it consumes by version pin rather than copying. The three family house rules are named alongside it.
- `labs/TASKS.md` records the local docs-preview recipe: the Jekyll stack builds from a scratch copy of `docs/` with `BUNDLE_PATH` outside the repo, so docs tokens are verifiable pre-push and the tree is never the build root.

### Fixed
- **`prestruct-shapes`: two checks did not test what they claimed (#69).** (1)
  `prestruct/placeholder-leaked` scanned for `your-site.example.com` and
  `<title>Your Site</title>` - neither token exists anywhere in prestruct, so the
  check PASSED on every tree unconditionally: a green light wired to nothing. It
  now scans the engine init shell's REAL placeholder strings (`init/index.html`:
  `yoursite.com` and `<title>Site</title>`), so a build that serves the
  un-injected template is caught. (2) `prestruct/deploy-id-drift` counted every
  `.html`, including the hand-authored `404.html` that is not part of the
  prerender stamp - a valid single-build tree whose 404 carries no deploy-id
  would FAIL. The comparison now scopes to mounted pages (the same `MOUNT_RE`
  filter the SSR-marker check uses), so "one build across the tree" means across
  the pages the engine rendered. (3) `pack.json`'s `env.fs.targets` dropped the
  `web/index.html` entry - prestruct ships no `web/`, so it never resolved. The
  negative test gained a second real placeholder token case and a shell-page
  no-deploy-id false-positive guard; the good bake stays clean 4/4.
- The served `/status.json` advertised a **404** docs URL: the emitter's `docs` field pointed at `https://docs.creadev.org/poststruct/status/`, but the docs page ships under the extensionless permalink `/status` (the form the docs sitemap advertises) - the trailing slash 404s on this host. `DOCS` now matches the permalink, and a new battery leg in `test/status.test.cjs` re-derives the URL from `docs/status.md`'s own frontmatter so the two cannot drift again (verified failing on the old value). The same dangling class exists on crashtest (`docs.creadev.org/crashtest/reference/status/` 404s; the no-slash form serves) - filed as a follow-up there.
- The shipped web copy still said "four repos" after monoforge joined the roster: the island subtitle, the `/status` page's family section, and the island's own header comment now name the family without a count, so adding the next member cannot leave the prose stale.
- The family grid is symmetric again: the `/status` island's sibling table now tracks **monoforge** (`https://monoforge.creadev.org`) alongside eyestruct, crashtest, poststruct, and packstruct, and the served `connect-src` grew the same origin in the same commit (#50). The two ship together by design - a member in the table without the CSP entry renders `Failed to fetch` forever, the exact trap #45 fixed. monoforge has no emitter yet, so its row reads as the honest "not serving the dialect yet" until it lands; the contract page's roster names it as tracked-before-shipping.
- The `/status` page's family-status island could not actually read the family in a browser: the served CSP was `connect-src 'self' https://cloudflareinsights.com`, so every sibling `fetch()` was refused before CORS ran and each row degraded to `Failed to fetch` instead of the contract's honest per-row absence. `web/public/_headers` now allows the member origins in `connect-src` and serves `/status.json` with its own `Access-Control-Allow-Origin: *` block (the canonical shape the other members carry, miss path included). A new battery leg in `test/status.test.cjs` reads the island's declared member origins and asserts each is in the shipped `connect-src` (verified failing on the old header), so the two cannot drift again. Found live after promotion (#45) - the same class crashtest fixed in `dhaupin/crashtest@977507e`.
- `scripts/check-jekyll-filters.cjs` also refuses an unknown Liquid tag now, the same build-time class it already guarded: `{% seo %}` written in `docs/packs.md` prose killed the docs deploy with `Unknown tag 'seo'` (backticks are markdown, not Liquid escaping, and the docs deliberately ship no theme gem or `jekyll-seo-tag` plugin). Literal tags are exempted when wrapped in `{% raw %}`, and the tag set is the Jekyll 4.x core, so the failure is named in `lint:docs` with a file:line instead of surfacing in Jekyll's stack trace.
- `publish.yml`'s ladder gate read the ref NAME, not the version: `!startsWith(github.ref_name, 'v0.')` was true for a `workflow_dispatch` run on `main` or `staging` (where `ref_name` is the branch), so a 0.x tree could publish from CI - the exact thing `DEPLOY.md` says CI blocks. The gate is now a job that reads the version out of `package.json` and feeds the `publish` job's `if:`, so nothing at 0.x can publish regardless of how the run was triggered.
- `npm run site:build` installs `web/` before building, so the verb is self-contained for the Pages build command (the prior form assumed a separate `web/` install).
- Root `dist/` and `web/.prestruct/` are gitignored: the landing build product and the prestruct build cache no longer show up as untracked files.
- The eyestruct pin drift is gone: the `run-packs.mjs` refusal text and `AGENTS.md` name the `1.0.0` pin (the stale `0.9.0` mentions are corrected), and the pack-lane row no longer claims packs are absent from the core.
- The docs lane builds again: freestruct 1.1.0's strict link checker resolves root-absolute hrefs against the artifact root with no `basePath` awareness, so the `/poststruct/...` nav failed every page (100 findings, dhaupin/freestruct#32, fixed upstream but unpublished). `linkCheck: false` suspends that one class until a pinned release carries the fix; the rest of the strict gate stays on. `scripts/check-docs-links.cjs` now reads the repo's own `SITE_PREFIX` (`/poststruct`, not the ported `/prestruct`) and catches the doubled-prefix class.
- The Cloudflare Pages build runs again: the dashboard ships the Vite preset default build command (`npm run build`), which the root had no script for, so every deploy died at `Missing script: "build"`. The root now aliases `build` to `site:build`, so the preset default and the documented contract resolve to the same verb.
- CI now verifies `staging`, not just `main`: the `test` and `docs` workflows trigger on push and pull_request for both branches, so work is checked where it lands instead of at promotion time. The `docs` deploy job is gated to `main`, so a `staging` build proves the lane without publishing to Pages.
- The promotion loop closes: a merge-commit promotion leaves `main` one commit ahead of `staging` every time, so `AGENTS.md` now names the fast-forward step that settles it.

### Changed
- `eyestruct-shapes` encodes the slot jail, the freeze-era manifest delta from issue #42. A route row's optional `slot:` becomes part of a candidates-dir file name and a canon slot key, so it is a page name only (`[\w-]+`); a path shape (`/`, `..`, separators, dots, spaces) now refuses `MANIFEST_CORRUPT`, mirroring eyestruct 1.0.0's `lib/manifest.js`. Before this the pack returned clean on `slot: ../escape` while the engine refused it, a false negative in a surface the freeze already shipped. The negative test grew `bad-slot-escape` and the good canon now carries a legal `slot: home`, so the jail's both directions are pinned (parity verified against eyestruct 1.0.0 across nine slot values).
- The Cloudflare Pages contract is named in one place: `DEPLOY.md`, `README.md`, and `wrangler.toml` now state the project settings (root directory empty, build command `npm run site:build`, build output directory `dist`) and record why a `web` root breaks the build (Pages resolves `pages_build_output_dir` against the root, so `dist` lands outside the repository, and the root `functions/` directory drops out of the project).

### Removed
- The scheduled `linkcheck.yml` workflow: it invoked a `linkcheck` CLI mode that does not exist in 0.9.0, so the weekly lane would have gone red on the first push. The weekly external-link gate returns with the links module + `--check-external` (M1, tracked in labs/TASKS.md).

## [0.9.0] - 2026-10-23

### Added
